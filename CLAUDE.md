# Virtuoso System (Virtuous Accounting Solutions CC)

Single-file demo app: `index.html` (vanilla JS, no build step). PWA files: `manifest.webmanifest`, `sw.js`, icons. Hosted with GitHub Pages from `main` (push to deploy): https://mrandrecloete-hub.github.io/virtuous-system/

## Facts
- Namibia, NAD, financial year March to February (FY2027 = Mar 2026 to Feb 2027).
- Demo data only, held in one `state` object; resets on reload. No backend yet.
- Demo logins: admin@firm.example / Admin#2026, selma@firm.example / Welcome#1, tobias@firm.example / Welcome#4 (must change password).
- Payroll is non-tax. Do not invent Namibian PAYE/SSC rates; they need verified, effective-dated rules.
- Brand: navy and gold theme, logo files `logo.png` (white background), `logo-dark.png` (transparent, for dark backgrounds). App name "Virtuoso System"; company name stays "Virtuous Accounting Solutions CC".

## Code layout (inside index.html)
- State and data near the top of the script; `VIEWS` map picks the page; `render()` rewrites `#view`; delegated click/submit/change/input handlers.
- Modules: dashboard, employees, timesheets, clients and billing, leave, loans, payroll and payslips, wet signature, petty cash (receipts, sheets, reconcile), stationery, cash taken, KYC forms builder, staff requests, reports, audit log, alerts.
- Excel upload uses SheetJS from cdnjs.

NO NUMBER IS INVENTED OR ALTERED (owner's requirement, Nov 2026): `resolveChain` only checks printed figures against each other; amounts and balances are never recalculated or repaired and the opening balance is never inferred (printed or typed only). Lines with no readable amount are kept and flagged, never dropped; low OCR confidence descriptions flagged. Each file shows a verification box (opening, total debits, total credits, closing calculated vs closing printed on the statement, difference; green AGREES / red DOES NOT AGREE; opening/closing can be typed from the statement; check only, never written into lines), editable lines, delete/add line, amounts shown with thousand commas and 2 decimals (Excel cells keep real numbers, format #,##0.00), Preview window (the exact Excel rows plus totals check, with Download Excel/CSV inside; action scPrev). Tested on one real FNB credit-card statement (Apr 2024, single amount column, no running balance, 'Cr' opening, space thousands like '1 263.88'): 35 lines, 17,137.39 debits, agrees with opening 5,268.43Cr and closing 11,868.96 owed (the check accepts balances shown as amounts owed, either as credit opening with owed closing, or both owed: opening + debits - credits = closing). The 'All statements' table reports 'Continues from <file>' by matching each opening to another file's closing. Not yet tested on other banks; other bank layouts may need adjustments. `ExcelJS` and the script are in the sw.js cache list.
